# Design fidelity — one verdict per invariant (phase 2)

Judged against `DESIGN.md`'s `## Invariants`. `fidelity ∈ UPHELD | AT-RISK | DROPPED`.

- **INV-1** — fidelity: UPHELD — Half A persists the SAME `AgentActivity` entry stream (via the shared `PersistingActivitySink` reusing `append_agent_activity`) to the background run's own `workflow_runs` row and renders it with the workflow `AgentActivityTimeline` (ITEM-2/3/4). No new timeline format; the after-completion view survives reload because it reads the durable `step_logs_json`.
- **INV-2** — fidelity: UPHELD — Half B models each fan-out child as its own `workflow_runs` row (`job_kind='subagent'`) carrying the full per-child activity (thinking + tool calls/results + messages), read back through the owner-scoped endpoint and rendered inline in `SubAgentActivityCard` via the same `AgentActivityTimeline` (ITEM-5/6/7/8/9). The persisted child transcript is complete, not a summary.
- **INV-3** — fidelity: UPHELD — the feature only adds a per-child persisting SINK + a child run row for USER display; it does NOT touch `summary_from_events`/`neutralize_untrusted` (fanout.rs:303/362) — the parent LLM still receives only the neutralized summary. ITEM-11 pins this: with no factory the fan-out is byte-identical, and an acceptance test asserts the parent transcript contains only the summary, never child raw output.
- **INV-4** — fidelity: UPHELD — every read is owner-scoped by `user_id` (detail reuses `get_background_run_detail`'s existing `WHERE user_id`; the new list adds `WHERE user_id = $auth AND job_kind='subagent'`); a foreign child id yields 404. Gated on the existing `WorkflowsRead` (Users group) — no new permission.
- **INV-5** — fidelity: UPHELD — `agent-core` gains only an injected `Option<Arc<dyn ChildSink>>` port whose surface is `(Uuid, &str) -> Arc<dyn EventSink>` + `settle_child(Uuid, bool)` — no DB/schema/server types enter the crate; `deps_boundary.rs` stays green. Absent factory ⇒ the exact current Noop behavior.
