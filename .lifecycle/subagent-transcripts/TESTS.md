# TESTS — Surface agent transcripts for background runs and fan-out children

Every ITEM is covered; every `INV-N` is pinned by an `[acceptance]` test. UI is
touched (ITEM-4, ITEM-9) so ≥1 `tier: e2e` is enumerated. No new permission is
introduced (WorkflowsRead is reused — see DEC), so no `[negative-perm]` spec is
required.

## Acceptance tests (one per design invariant)

- **TEST-1** (tier: integration) [acceptance] [invariant: INV-1] [covers: ITEM-2, ITEM-3] file: `src-app/server/tests/background_mcp/transcript_test.rs` — asserts: a background run driven to completion persists its agent-loop activity, and `GET /api/background/runs/{id}` returns an `activity[]` containing thinking + tool_call + message entries, owner-scoped (the after-completion transcript INV-1 promises), rendered-ready for `AgentActivityTimeline`.
- **TEST-2** (tier: integration) [acceptance] [invariant: INV-2] [covers: ITEM-6, ITEM-7, ITEM-8] file: `src-app/server/tests/workflow/subagent_runs_test.rs` — asserts: driving the REAL server fan-out path (`ChatChildSinkFactory::for_child` → stream a child transcript → `settle_child`) creates a child `workflow_runs` row (`job_kind='subagent'`, `parent_message_id` set) and `GET /api/subagent-runs/{child_id}` returns that child's FULL per-child activity (thinking + tool + message), read back via the endpoint. (The agent-core→factory wiring is proven separately by TEST-3/TEST-5; the real end-to-end chat fan-out by the e2e TEST-13.)
- **TEST-3** (tier: unit) [acceptance] [invariant: INV-3] [covers: ITEM-5, ITEM-11] file: `src-app/agent-core/src/fanout.rs` — asserts: with a child-sink factory PRESENT and a child that emits distinctive raw output, the parent still receives ONLY the neutralized summary — the returned `SubagentSummary`/parent event stream never contains the child's raw tool output (persist-for-display ≠ feed-back-to-parent).
- **TEST-4** (tier: integration) [acceptance] [invariant: INV-4] [covers: ITEM-8] file: `src-app/server/tests/workflow/subagent_runs_test.rs` — asserts: user B requesting user A's subagent child id (and A's background run id) gets 404, never the row — owner-scope holds on every transcript read.
- **TEST-5** (tier: unit) [acceptance] [invariant: INV-5] [covers: ITEM-5, ITEM-11] file: `src-app/agent-core/src/fanout.rs` — asserts: with `child_sink_factory=None` the fan-out is byte-identical to the Noop path (children run on `NoopEventSink`, summary-only), proving child-activity persistence needs no DB/schema dependency inside the crate.
